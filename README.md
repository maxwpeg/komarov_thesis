# Кульман

`Кульман` - веб-приложение для работы с архитектурными планами и подготовки проектной документации систем безопасности. Система помогает загрузить план этажа, распознать элементы чертежа, уточнить результат в редакторе, разместить оборудование, сформировать PDF-документы и сохранить историю проекта.

Проект состоит из нескольких частей:

- `frontend` - пользовательский интерфейс на React, который открывается в браузере.
- `backend` - FastAPI-сервер с бизнес-логикой, распознаванием, PDF-генерацией, аудитом и фоновыми задачами.
- `postgres` - база данных для проектов, пользователей, оборудования, задач и версий документов.
- `app_data` - файловое хранилище для загруженных планов, PDF, артефактов распознавания и дообучения.

## Быстрый Запуск

Для запуска нужен Docker Desktop или Docker Engine с Docker Compose.

Из корня проекта выполните одну команду:

```powershell
docker compose up -d
```

После запуска откройте:

- приложение: `http://localhost:3000`
- backend API и Swagger: `http://localhost:8000/docs`
- healthcheck backend: `http://localhost:8000/health/ready`

Compose тянет готовые образы из Docker Hub:

- `maxwpeg/kulman-frontend:latest`
- `maxwpeg/kulman-backend:latest`
- `postgres:16-alpine`
- `alpine:3.20`

Локальная сборка образов не требуется.

## Первый Запуск И Данные

При первом запуске Docker Compose поднимает PostgreSQL и файловое хранилище, затем выполняет одноразовую инициализацию:

- `db-seed` переносит подготовленный снимок базы из `docker/seed/database/floor_plans_seed.db` в PostgreSQL;
- `storage-init` копирует файлы из `docker/seed/files` в Docker volume `app_data`;
- backend запускается с `RUN_INLINE_WORKER=1`, поэтому фоновые задачи выполняются внутри backend-контейнера.

Данные хранятся в Docker volumes:

- `postgres_data` - база PostgreSQL;
- `app_data` - загруженные файлы, PDF, логи, артефакты распознавания и дообучения.

Остановка без удаления данных:

```powershell
docker compose down
```

Полный сброс Docker-данных:

```powershell
docker compose down -v
```

После `down -v` следующий запуск снова восстановит стандартное состояние из seed-данных.

## Как Пользоваться

1. Войдите в систему через страницу авторизации. Роль `developer` используется как административная: ей доступны пользователи, аудит, дообучение и служебные операции.
2. Откройте список проектов или создайте новый проект.
3. В карточке проекта добавьте этаж и загрузите изображение плана.
4. Запустите распознавание. Длительные операции отображаются как фоновые задачи с прогрессом.
5. Проверьте результат в редакторе: стены, помещения, проемы, оборудование, извещатели и кабельные трассы можно уточнять вручную.
6. Используйте каталог оборудования для добавления и настройки устройств.
7. Запустите авторасстановку пожарных извещателей, если нужно получить первичное проектное решение.
8. Сформируйте PDF-документацию. Каждая генерация сохраняется как отдельная версия PDF в проекте.
9. В разделе аудита можно посмотреть важные действия пользователей и выгрузить журнал в CSV или JSON.
10. В разделе дообучения можно собирать исправления распознавания, запускать обучение и активировать подходящую модель.

## Основные Возможности

- управление проектами, этажами и планами помещений;
- загрузка изображений планов с серверной проверкой файлов;
- распознавание стен, проемов, помещений и размерных подписей;
- ручное редактирование плана в браузере;
- каталог оборудования с файлами, характеристиками и привязкой к проектам;
- автоматизированная расстановка пожарных извещателей;
- фоновые задачи с прогрессом, стадиями и повторным запуском failed-задач;
- генерация PDF-документации через ReportLab;
- хранение версий PDF-документов;
- административный аудит с фильтрами и экспортом;
- дообучение распознавания на основе пользовательских исправлений;
- контейнерный запуск всей системы одной командой.

## Настройки

Основные переменные можно задать в `.env` или взять за основу файл `.env.docker.example`:

- `FRONTEND_PORT` - внешний порт frontend, по умолчанию `3000`.
- `BACKEND_PORT` - внешний порт backend, по умолчанию `8000`.
- `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` - параметры PostgreSQL.
- `BOOTSTRAP_DEVELOPER_USERNAME`, `BOOTSTRAP_DEVELOPER_FULL_NAME`, `BOOTSTRAP_DEVELOPER_PASSWORD` - учетная запись разработчика для пустой базы.
- `CORS_ALLOWED_ORIGINS` - разрешенные origins frontend.
- `AUTH_COOKIE_SECURE` - флаг secure-cookie для HTTPS-развертывания.

В контейнерах backend использует `DATABASE_URL` для подключения к PostgreSQL и `DATA_DIR=/data` для файлового хранилища.

## Локальная Разработка

Обычный пользовательский запуск выполняется через Docker. Для разработки можно запускать части отдельно.

Backend:

```powershell
cd backend
python -m pip install -r requirements.txt
uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Frontend:

```powershell
cd frontend
npm install
npm start
```

## Ограничения

- Загрузка планов рассчитана на изображения; PDF поддерживаются как документы и артефакты, но не как основной формат импортируемого плана.
- Качество распознавания зависит от качества исходного плана: шумные, перекошенные и неортогональные чертежи требуют ручной проверки.
- Docker-хранилище использует локальные named volumes, поэтому резервное копирование остается эксплуатационной задачей.
- Seed-данные являются снимком демонстрационного состояния, а не полноценным механизмом миграции рабочих окружений.
