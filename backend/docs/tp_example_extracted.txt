                                      1   ВВЕДЕНИЕ

       1.1       Наименование программы

          Наименование программы: «Приложение для знакомств, общения и встреч
   “Swiply”».
          Наименование программы на английском языке: «Application for Dating,
   Communication and Meetings "Swiply"».
          Краткое наименование программы: «Swiply».

       1.2       Краткая характеристика области применения программы

         Программа является частью комплекса программ приложения Swiply, который
   состоит из iOS клиента, серверной части и административной панели. Серверная часть
   реализует логику приложения Swiply и предоставляет API для взаимодействия клиентов с
   сервисами приложения.
         Swiply позволяет находить интересных людей для общения и встреч. Пользователь
   просматривает анкеты других людей и отмечает понравилась анкета или нет. В приложении
   есть чат, в котором пользователи смогут общаться после взаимной симпатии.
          Приложение использует рекомендательную систему для подбора пользователям
   наиболее релевантных для них анкеты с точки зрения их предпочтений и интересов.
          Административная      панель    позволяет   просматривать   анкеты   пользователей
   осуществлять модерацию (блокировать неприемлемые анкеты).
         Также пользователь может создавать мероприятия и подавать заявку на участие в
   них. Если организатор принимает пользователя, то он попадает в чат, в котором сможет
   обсудить детали мероприятия с организатором.

                                   2    ТЕКСТ ПРОГРАММЫ

          Полный текст программы расположен в публичном GitHub-репозитории: the-
   swiply/swiply-backend [13].

          Программа состоит из 5 сервисов, код каждого из которых расположен в отдельной
   директории с названием сервиса. Для каждого сервиса также выделена директория вида
   “имя-сервиса-infa”, содержащая файлы для поднятия инфраструктуры сервиса с помощью
   Docker [9].

          Также в корне репозитории расположен docker-compose.yml файл для запуска
   приложения локально с помощью Docker [9].

          Каждый из Go [11]-сервисов имеет единую структуру, опирающуюся на go-standard-
   layout [12]. Состав директорий следующий:

               •   api – содержит proto-файлы с описанием API
               •   cmd – содержит точку входа в программу
               •   configs – содержит конфигурационные файлы
               •   migrations – содержит файлы миграций баз данных
               •   pkg/api – содержит сгенерированные на основе proto файлы текущего сервиса
               •   pb - содержит сгенерированные на основе proto файлы сервисов от которого
                   зависит текущий
               •   third_party/swagger – содержит файлы Swagger [15]-документации
               •   internal – основная директория с кодом сервиса
               •   app – создание зависимостей и запуск сервиса
               •   domain – доменные сущности приложения
               •   server – HTTP [16] и gRPC [14] серверы
               •   service – бизнес-логика сервиса
               •   и другие пакеты-обертки над инфраструктурой сервиса

       2.1         Платформенные пакеты

          Внутри директории pkg/houston расположены общие Go []-пакеты, которые могут
   быть использованы любым из сервисов (платформенные пакеты, необходимы для
   стандартизации работы в условиях нескольких разработчиков).

       2.2         Сервис пользователей (user)

          Сервис предоставляет функционал для взаимодействия с пользователем как с
   сущностью по его ID, в частности в нем реализована авторизация пользователя. Расположен
   в директории user.

       2.3         Сервис чата (chat)

          Сервис предоставляет реализацию многопользовательского чата с поддержкой
   работы в режиме нескольких экземпляров. Хранит и обрабатывает сообщения внутри чатов
   и работу самих чатов.

       2.4         Сервис рекомендаций (recommendation)

          Сервис предоставляет основной функционал по рекомендации релевантных анкет и
   является единой точкой взаимодействия со всеми сервисами, необходимыми для
   рекомендаций.

       2.5         Сервис оракул (oracle)

          Сервис является вспомогательным сервисом для recommendation. Осуществляет
   вычисление релевантности анкет пользователей друг относительно друга с использованием
   рекомендательных алгоритмов на основе машинного обучения.

       2.6         Сервис администрации (backoffice)

          Сервис предоставляет функционал модерации анкет пользователей приложения.
   Структура директорий и файлов советует стандартной структуре Django [10].
